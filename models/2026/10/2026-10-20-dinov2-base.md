# DINOv2-base: 라벨 분류 head 없이 쓰는 12층 이미지 특징 encoder

조사일: 2026-10-20 KST. ID `facebook/dinov2-base`, revision `f9e44c814b77203eaa57a6bdbbd535f21ede1415`.

## 선정과 식별

Meta DINOv2의 ViT-B/14 이미지 특징 모델이다. 작은 모델은 큰 ViT-g 교사에서 증류하는 계열이며 정확한 교사 revision은 확인 불가다. 라이선스는 Apache-2.0이다. 논문 최초 공개는 2023-04-14이며 해당 HF 체크포인트의 정확한 최초 배포일과 구분한다. HF 카드는 Hugging Face 팀 작성이다. [고정 카드](https://huggingface.co/facebook/dinov2-base/blob/f9e44c814b77203eaa57a6bdbbd535f21ede1415/README.md), [논문 기록](https://arxiv.org/abs/2304.07193)

조사 시점 최근 한 달 다운로드 3,106,054회·좋아요 212개였다. 좋아요 집계 기간은 확인 불가이며 인기 지표는 품질의 증거가 아니다. [모델 페이지](https://huggingface.co/facebook/dinov2-base), [API](https://huggingface.co/api/models/facebook/dinov2-base)

모든 기존 models·issues 파일을 읽어 동일 모델 분석이 없음을 확인했다. 앞선 Google ViT와 구조적 관련은 있지만 별도 자기지도·증류 학습을 거친 특징 모델이며 단순 미러·양자화 변형이 아니다. 가중치 다운로드·추론·학습은 수행하지 않았다.

## 구조와 전처리

표는 [고정 config](https://huggingface.co/facebook/dinov2-base/blob/f9e44c814b77203eaa57a6bdbbd535f21ede1415/config.json), [processor 설정](https://huggingface.co/facebook/dinov2-base/blob/f9e44c814b77203eaa57a6bdbbd535f21ede1415/preprocessor_config.json) 및 조사 당시 API 집계에 근거한다.

| 항목 | 값 |
|---|---|
| 유형 | Dinov2Model, dense vision encoder |
| 파라미터 | 86,580,480 F32 원소, 약 86.6M |
| Transformer layers | 12 |
| hidden dimension | 768 |
| heads | 12, 별도 GQA KV heads 설정 없음 |
| head dimension | 768÷12=64, 균등 분할 가정 계산 |
| MLP ratio / 폭 | 4 / 계산상 3,072 |
| 활성화 / SwiGLU | GELU / use_swiglu_ffn=false |
| patch size | 14×14 |
| config image_size | 518 |
| 기본 전처리 | 짧은 변 256 resize → 224×224 center crop |
| 위치 표현 | absolute 위치 임베딩, 카드 설명 |
| QKV bias | true |
| LayerNorm epsilon | 1e-6 |
| layerscale_value | 배포 config 1.0, 학습 초기값과 구분 |
| fine-tuned head | 없음 |
| MoE·멀티모달 | 없음; MoE식 활성 파라미터 구분 해당 없음 |

**계산:** 224 입력이면 (224÷14)²=256개 패치, CLS 포함 257개 위치다. 518 입력이면 (518÷14)²=1,369개 패치, CLS 포함 1,370개다. 이는 해당 크기 입력을 가정한 계산이며 기본 processor가 자동으로 518을 넣는다는 뜻은 아니다. 고해상도 입력 처리·위치 보간은 실행 구현도 함께 확인해야 한다.

이미지를 패치로 나눈 뒤 서로 참조하는 attention으로 표현을 갱신한다. CLS는 이미지 전체 표현, patch token은 위치별 표현으로 활용할 수 있다. 분류·분할을 하려면 용도에 맞는 head 또는 비교 규칙을 추가한다. 카드의 head 없는 기본 모델에서 곧바로 ImageNet 라벨 점수가 나오지는 않는다. [고정 카드](https://huggingface.co/facebook/dinov2-base/blob/f9e44c814b77203eaa57a6bdbbd535f21ede1415/README.md)

논문 v2 표 17에는 distilled ViT-B/14를 18 blocks로 적지만 고정 HF config는 12층이다. 이 글은 배포 설정 12를 사용하고 두 자료가 일치한다고 쓰지 않는다. [논문 부록 B](https://arxiv.org/html/2304.07193v2#A2)

## 학습: 계열 레시피와 실제 배포 기록 구분

아래 값은 논문 v2 표 16의 **DINOv2-B distilled** 조건이다. HF 체크포인트의 실제 실행 로그를 확보한 것은 아니다. [논문 부록 B.1](https://arxiv.org/html/2304.07193v2#A2.SS1)

| 항목 | 공개 레시피·확인 상태 |
|---|---|
| 방식 | 큰 고정 교사로부터 작은 학생 증류; 최종 학생 EMA 사용 |
| epoch | 확인 불가 |
| iterations | 논문 625K |
| batch | 2,048 |
| learning rate | 1e-3 |
| warmup | 100K iterations |
| optimizer | AdamW |
| weight decay | cosine schedule 0.04→0.2 |
| precision | 논문 FP16, DINO head gradient reduction FP32 예외 |
| gradient accumulation | 확인 불가 |
| B 모델 전용 하드웨어·시간 | 확인 불가 |
| 실제 체크포인트 소비 이미지 수 | 확인 불가 |
| 별도 SFT·DPO·RL·LoRA | 적용 근거 확인 불가 |

일반 자기지도 사전학습과 작은 모델 증류는 동일 절차가 아니다. 논문은 증류 때 masking·stochastic depth를 제거하는 차이를 설명한다. 고해상도 적응도 별도 단계를 설명하지만 배포본의 개별 실행 로그와 대응을 확정하지 못했다. Layers·iterations·데이터 반복인 epoch를 서로 바꾸어 쓰지 않는다.

공식 [DINOv2 저장소](https://github.com/facebookresearch/dinov2)의 vitb14 학습 설정 경로 조회는 실패해 해당 파일을 확인했다고 쓰지 않았다. 이 표의 학습 수치는 논문 기준이며 config의 layerscale_value=1.0을 학습 초기 LayerScale 값으로 취급하지 않는다. 미확인 항목은 추정하지 않았다.

## 평가와 비교

보고서는 이미지 분류뿐 아니라 이미지 검색·분할·깊이 추정 등에서 고정 특징을 평가한다. Linear probe는 encoder를 고정하고 라벨로 작은 head를 학습하는 조건이며, 학습하지 않은 기본 모델이 곧바로 해당 과제를 완수한다는 뜻은 아니다. 같은 이미지 split·해상도·head 학습·특징 조합을 맞춰 비교해야 한다. [논문 평가 설명](https://arxiv.org/html/2304.07193v2#S7)

이번 조사에서는 배포본과 개별 평가 설정의 완전한 대응을 검증하지 못해 계열 최고 점수를 이 base 모델의 실측으로 제시하지 않는다. 자기지도 학습이라는 말도 데이터 수집·평가에서 인간 라벨이 전혀 사용되지 않았다는 뜻으로 넓혀 해석하지 않는다.

기존 [Google ViT 분석](2026-10-13-vit-base-patch16-224.md)은 16×16 패치와 1,000개 분류 라벨 head를 가진다. 이번 모델은 14×14 패치와 head 없는 시각 특징 출력이 핵심이다. CLS의 폭이 같아도 서로 다른 모델의 벡터를 같은 공간으로 간주할 수 없다.

## 활용과 제약

이미지 유사도·분류용 head 학습·위치별 특징 분석의 출발점으로 검토할 수 있다. 텍스트 encoder와 공동 공간을 학습한 CLIP처럼 텍스트 질의를 직접 비교하거나 사진 설명을 생성하는 모델은 아니다. 도메인 변화·crop으로 잘린 대상과 세부 영역의 성능은 별도 검증해야 한다.

F32 가중치만 가정하면 `86,580,480×4≈346.3 MB`(십진)다. 이는 계산값이며 최소 VRAM·실측이 아니다. 입력 해상도에 따른 token 수·activation·batch·런타임 버퍼가 추가된다. 속도와 정확도는 직접 측정하지 않았다.
