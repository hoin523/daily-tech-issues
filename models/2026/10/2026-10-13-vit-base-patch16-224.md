# ViT-B/16-224: 이미지를 196개 패치로 읽는 12층 분류 모델

조사일: 2026-10-13 KST. ID `google/vit-base-patch16-224`, revision `3f49326eb077187dfe1c2a2bb15fbd74e6ab91e3`.

## 선정과 식별

Google Research의 Vision Transformer 계열 이미지 분류 모델이다. 조사 당시 최근 한 달 다운로드 12,572,838회·좋아요 1,022개를 확인했다. 좋아요 집계 기간은 확인 불가이며 인기 지표는 성능 증거가 아니다. [모델 페이지](https://huggingface.co/google/vit-base-patch16-224), [API](https://huggingface.co/api/models/google/vit-base-patch16-224)

ImageNet-21k 사전학습 후 ImageNet-1k 분류용으로 fine-tuning한 모델이다. HF 카드는 Hugging Face 팀이 작성했으며 Google 연구팀 자체 카드와 구분한다. 가중치는 JAX→timm PyTorch→HF 변환 계보를 가진다. 라이선스는 Hub 표기 Apache-2.0이다. 정확한 체크포인트 최초 발표일은 확인 불가이며 원 논문 최초 공개일 2020-10-22와 구분한다. [고정 모델 카드](https://huggingface.co/google/vit-base-patch16-224/blob/3f49326eb077187dfe1c2a2bb15fbd74e6ab91e3/README.md), [논문 기록](https://arxiv.org/abs/2010.11929)

모든 기존 models·issues 기록을 읽어 동일 모델 분석이 없음을 확인했다. CLIP의 ViT 이미지 인코더와 관련은 있지만 이번 모델은 ImageNet 라벨 분류용이며 동일 모델·미러 변형이 아니다. 가중치 다운로드·추론·학습은 수행하지 않았다.

## 구조

아래 값은 [고정 config](https://huggingface.co/google/vit-base-patch16-224/blob/3f49326eb077187dfe1c2a2bb15fbd74e6ab91e3/config.json), [전처리 설정](https://huggingface.co/google/vit-base-patch16-224/blob/3f49326eb077187dfe1c2a2bb15fbd74e6ab91e3/preprocessor_config.json)에 근거한다. 파라미터 수는 조사 당시 HF API safetensors 집계다.

| 항목 | 값 |
|---|---|
| 유형 | ViTForImageClassification, dense encoder + 분류 head |
| 총 파라미터 | 86,567,656 (약 86.6M) |
| Transformer layers | 12 |
| hidden / FFN intermediate | 768 / 3,072 |
| attention heads | 12, 별도 GQA KV heads 설정 없음 |
| head dimension | 768÷12=64, 균등 분할 가정 계산 |
| 입력 | RGB 224×224 |
| 패치 | 16×16 |
| attention | 패치·CLS 간 full self-attention |
| 위치 표현 | 학습 가능한 absolute 위치 임베딩 |
| activation / LayerNorm epsilon | GELU / 1e-12 |
| QKV bias | true |
| 분류 출력 | ImageNet-1k의 1,000개 라벨 |
| MoE·활성 전문가 | 없음; MoE식 활성 파라미터 구분 해당 없음 |
| 멀티모달·decoder·VAE | 없음 |

위치 표현·CLS와 attention 방식은 [원 논문 §3.1](https://arxiv.org/html/2010.11929v2#S3.SS1)에도 설명돼 있다. 이미지 분류 모델에 LLM의 텍스트 context length나 KV cache 기준을 억지로 적용하지 않는다.

**계산:** 224÷16=14이므로 14²=196개 이미지 패치다. CLS 하나를 더하면 197개 위치를 처리한다. 각 RGB 패치의 원소 수는 16×16×3=768이며 이를 학습된 투영으로 hidden 768차원에 옮긴다. 숫자가 같아도 투영이 단순 복사라는 뜻은 아니다.

각 패치가 다른 패치와 정보를 교환하고 CLS 표현이 전체 이미지의 분류 신호를 모은다. 마지막 head는 1,000개 고정 라벨 점수를 낸다. 자유로운 문장 질문에 답하거나 새로운 라벨을 문장으로 넣어 비교하는 CLIP 방식과 다르다.

전처리는 크기 224로 resize하고 채널별 mean·std를 모두 0.5로 둔다. 정확한 이미지 처리 버전·resize 방식에 따라 입력이 달라질 수 있으므로 재현 때 processor도 함께 고정해야 한다. [전처리 설정](https://huggingface.co/google/vit-base-patch16-224/blob/3f49326eb077187dfe1c2a2bb15fbd74e6ab91e3/preprocessor_config.json)

## 학습: 논문 레시피와 체크포인트 구분

[논문 표 3·4](https://arxiv.org/html/2010.11929v2#A2)은 아래 실험 조건을 제공한다. 이 조건은 논문 레시피이며 HF 변환 체크포인트의 실제 실행 로그를 확보한 것은 아니다.

| 항목 | ViT-B/16 ImageNet-21k 사전학습 | ImageNet fine-tuning 논문 실험 |
|---|---|---|
| 데이터 | ImageNet-21k, 카드 약 14M 이미지 | ImageNet-1k, 카드 약 1M 이미지 |
| epoch | 논문 90; HF 실제 완료 횟수 확인 불가 | 확인 불가 |
| step | 실제 체크포인트 로그 확인 불가 | 논문 20,000; 224 배포본 실행값 확인 불가 |
| batch | 4,096 | 512 |
| optimizer | Adam | SGD momentum 0.9 |
| learning rate | 1e-3 | 논문 grid search; 배포본 선택값 확인 불가 |
| scheduler | 10K-step warmup, linear decay | cosine decay |
| gradient accumulation | 확인 불가 | 확인 불가 |
| precision / 하드웨어 | 체크포인트 실행 정보 확인 불가 | 확인 불가 |
| 별도 DPO·RL·LoRA | 적용 근거 없음 | 적용 근거 없음 |

논문 fine-tuning은 기본 384 해상도이고 여기 배포본은 224다. 따라서 같은 계열이라는 이유로 fine-tuning 조건을 전부 실제 실행값으로 확정하지 않는다. Epoch는 데이터 반복 횟수, step은 업데이트 횟수, 12 layers는 구조 깊이다. 논문의 JFT 학습이나 self-supervised 실험 조건도 이 ImageNet-21k 모델 학습량으로 옮겨 적지 않았다.

공식 [vision_transformer 저장소](https://github.com/google-research/vision_transformer)의 코드·체크포인트 설명도 확인했다. 현재 저장소 예시의 기본값을 과거 HF 모델의 실제 학습 로그로 간주하지 않는다. 미확인 값은 ‘확인 불가’로 표시했다.

## 평가·비교·활용

원 논문 표 5는 ImageNet-21k 사전학습 ViT-B/16의 ImageNet top-1 83.97%를 보고한다. 그러나 표는 384 해상도 fine-tuning 결과이므로 이 224 배포본의 정확도로 인용할 수 없다. 동일 데이터 split·resize/crop·해상도·평가 방식의 체크포인트 결과를 이번 조사에서 검증하지 못해 배포본 성능 점수는 제시하지 않는다. [논문 표 5](https://arxiv.org/html/2010.11929v2#A3)

이전 [CLIP ViT-B/32 분석](2026-10-09-clip-vit-base-patch32.md)은 32×32 패치와 이미지·텍스트 대조학습을 사용한다. 같은 224 입력을 가정하면 이미지 패치 수는 49개 대 196개다. 패치가 작아지면 토큰 수가 늘지만 목표와 학습 데이터가 달라 이것만으로 정확도 우열을 판단할 수 없다.

고정 ImageNet 범주의 분류나 새로운 이미지 라벨 데이터로 fine-tuning하는 출발점으로 검토할 수 있다. 라벨 목록 밖의 대상, 도메인이 다른 산업 이미지, 여러 물체의 위치 검출에는 별도 평가·모델 구성이 필요하다. Softmax 최고 점수가 실제 정답 확률로 잘 보정됐다는 보장도 없다.

F32 가중치만 가정하면 `86,567,656×4≈346.3 MB`(십진)다. 계산값이며 최소 VRAM·실측이 아니다. Activation·배치·실행 버퍼가 추가되며 추론 속도와 정확도도 직접 측정하지 않았다.
