# OLMo-1B: 16층 MHA와 학습 가능한 계수가 없는 LayerNorm

조사일: 2026-10-27 KST. 가중치를 다운로드하거나 추론·학습하지 않고 공개 자료를 분석했다.

## 선정과 식별

모델 ID는 `allenai/OLMo-1B-hf`, revision은 `aee7752d9c08ee4775e9b0091426d8410e8f6a89`다. 조사 시 [Hub API](https://huggingface.co/api/models/allenai/OLMo-1B-hf)는 다운로드 30,267·좋아요 29를 반환했다. [페이지](https://huggingface.co/allenai/OLMo-1B-hf)의 다운로드 집계 기간은 last month다. 인기도는 성능이나 고유 사용자 수의 증거가 아니다. 초대형 인기 모델보다는 사용 지표가 작지만, 공개 학습 자료를 읽기 좋은 원본 계열 모델로 선정했다.

기존 models·issues의 전체 파일을 읽어 OLMo 계열 구조 분석이 없음을 확인했다. 이미지·텍스트와 음악에 이어 텍스트 사전학습 모델, 개발 조직 Ai2를 선택했다. HF 형식 변환본이므로 `allenai/OLMo-1B`를 별도 모델로 다시 선정하지 않을 대상에 포함한다.

개발은 Allen Institute for AI, 용도는 영어 다음 토큰 예측과 언어 모델 연구다. [카드](https://huggingface.co/allenai/OLMo-1B-hf/blob/aee7752d9c08ee4775e9b0091426d8410e8f6a89/README.md)는 원본 OLMo-1B의 Transformers 형식 변환임을 명시하며, 다른 LLM에서 후처리한 대화 모델이라고 설명하지 않는다. 라이선스는 Apache-2.0이다. [논문 최초 제출](https://arxiv.org/abs/2402.00838)은 2024-02-01이며 이 날짜와 변환 체크포인트의 배포일은 구분한다. 변환본의 정확한 최초 배포일은 이번 조사에서 확인 불가다.

## 구조

[고정 HF config](https://huggingface.co/allenai/OLMo-1B-hf/blob/aee7752d9c08ee4775e9b0091426d8410e8f6a89/config.json), [원본 고정 config](https://huggingface.co/allenai/OLMo-1B/blob/344d48f1ef038097ed9471da33ddf2721e59f474/config.json), [Transformers v4.40.0 구현](https://github.com/huggingface/transformers/blob/v4.40.0/src/transformers/models/olmo/modeling_olmo.py)을 함께 대조했다.

| 항목 | 값·해석 |
|---|---|
| 종류 | OlmoForCausalLM, dense decoder-only |
| 총 파라미터 | 1,176,764,416, Hub safetensors 메타데이터 |
| 레이어 | 16 |
| hidden / FFN intermediate | 2,048 / 8,192 |
| Q heads / KV heads | 16 / 16, MHA |
| head dimension | 2,048÷16=128, 균등 분할 계산 |
| 문맥 길이 | 2,048 tokens |
| 위치 표현 | RoPE, theta=10,000, rope_scaling=null |
| MLP | SwiGLU; SiLU(gate)×up → down projection |
| 정규화 | affine weight·bias가 없는 LayerNorm |
| bias | attention·MLP 선형층 bias 없음 |
| 입력·출력 임베딩 | 가중치 공유 |
| 저장 dtype | float32; 실제 학습 precision과 별개 |
| 어휘 슬롯 | HF config 50,304 |
| MoE·멀티모달 | 해당 없음; 활성 전문가 수 구분 적용 안 함 |

원본은 `vocab_size=50280`, `embedding_size=50304`를 나누어 적지만 변환 config는 `vocab_size=50304`로 적는다. 실제 토크나이저 어휘와 행렬 슬롯을 동일한 개념으로 취급하지 않는다. 원본 MLP는 `mlp_ratio=8`이고 gated activation 전 합동 폭을 나타내는 반면, HF 구현은 gate·up 각각 8,192차원 projection으로 표현한다. 서로 다른 표기에서 구조가 달라졌다고 곧바로 결론 내리지 않는다. [원본](https://huggingface.co/allenai/OLMo-1B/blob/344d48f1ef038097ed9471da33ddf2721e59f474/config.json), [변환 구현](https://github.com/huggingface/transformers/blob/v4.40.0/src/transformers/models/olmo/modeling_olmo.py).

16개 블록은 앞서 나온 토큰을 참조해 다음 토큰의 표현을 만든다. Q와 KV head 수가 같아 Qwen3·Mistral에서 보았던 GQA식 KV 공유를 하지 않는다. SwiGLU는 두 변환 중 한쪽을 SiLU로 조절하고 다른 쪽과 곱해 정보를 통과시킨다. Non-parametric LayerNorm은 평균·분산 정규화를 하되 학습 가능한 gain과 bias를 두지 않는다는 뜻이다. 정규화 계산 자체가 없거나 학습이 없는 모델이라는 뜻은 아니다. [고정 구현](https://github.com/huggingface/transformers/blob/v4.40.0/src/transformers/models/olmo/modeling_olmo.py).

HF MLP 설정의 비율은 `8192÷2048=4`다. 카드의 상세 비교표는 **7B** 구조를 설명하므로 그 표의 약 8/3 비율·임베딩 비공유를 1B에 옮기지 않았다. [카드](https://huggingface.co/allenai/OLMo-1B-hf/blob/aee7752d9c08ee4775e9b0091426d8410e8f6a89/README.md).

## 학습: 1B의 값과 계열 설명을 구분

카드의 1B 행은 **3T training tokens**라고 쓰지만 논문 v3 표 1은 1B **2T**를 기재한다. 논문 §3.3은 2T-token Dolma 학습 표본을 한 번 통과한 것을 1 epoch라고 설명하고, 일부 모델의 추가 학습도 언급한다. 따라서 논문의 초기 이력과 카드의 후속 표기를 섞어 이 revision의 확정 epoch나 optimizer step을 만들지 않았다. [고정 카드](https://huggingface.co/allenai/OLMo-1B-hf/blob/aee7752d9c08ee4775e9b0091426d8410e8f6a89/README.md), [논문 §3](https://arxiv.org/html/2402.00838v3#S3).

| 항목 | 공개 근거와 적용 범위 |
|---|---|
| 단계·목표 | 사전학습, 다음 토큰 예측; Dolma 영어 중심 데이터 |
| 처리 토큰 | 카드 1B: 3T; 논문 v3 표 1: 2T, 시점 차이 주의 |
| epoch | 해당 HF revision의 정확한 값 확인 불가 |
| optimizer steps | 해당 HF revision의 정확한 최종 step 확인 불가 |
| global batch | 논문 1B·7B 공통 설명: 2,048 instances×2,048 tokens=4,194,304 tokens |
| microbatch / accumulation | 1B의 실행별 값 확인 불가 |
| optimizer | AdamW |
| peak LR | 1B 4e-4 |
| betas / epsilon / weight decay | 1B (0.9,0.95) / 1e-5 / 0.1 |
| scheduler | 논문 공통: 5,000-step warmup 뒤 선형 감소, peak의 1/10까지 |
| clipping | warmup 뒤 global gradient norm 1.0 |
| precision | 원본 config amp_bf16; 논문은 BF16 혼합 정밀도, local 가중치·optimizer state·gradient reduction FP32 설명 |
| 하드웨어 | 논문은 MI250X 기반 LUMI와 A100-40GB 기반 MosaicML을 설명; 1B revision별 GPU 수·기종 대응은 확인 불가 |
| SFT·DPO·RL·LoRA | 이 base 체크포인트에 별도 적용했다는 근거 확인 불가 |

학습 표의 근거는 [논문 §3.1~3.4·표 4](https://arxiv.org/html/2402.00838v3#S3), [원본 config](https://huggingface.co/allenai/OLMo-1B/blob/344d48f1ef038097ed9471da33ddf2721e59f474/config.json), [카드의 1B optimizer 표](https://huggingface.co/allenai/OLMo-1B-hf/blob/aee7752d9c08ee4775e9b0091426d8410e8f6a89/README.md)다. 카드에 있는 7B 전용 batch 2,160·optimizer 비교·환경 영향 표는 1B 자료로 쓰지 않았다. 논문의 7B microbatch 4,096 tokens/GPU도 1B 설정으로 옮기지 않았다. ‘확인 불가’는 이번 조사에서 대응 근거를 확인하지 못했다는 뜻이다.

계산 예시로, 카드의 3T가 정확하고 위 global batch가 끝까지 일정하다고 가정하면 `3×10^12÷4,194,304≈715,256` 업데이트다. 이는 반올림 토큰 총량에서 유도한 근삿값이며 최종 체크포인트 step의 확인값이 아니다. Epoch는 데이터 전체 반복, step은 갱신, 16 layers는 구조 깊이, 추론 출력 길이는 생성 토큰 수이므로 서로 치환할 수 없다.

## 평가·비교·활용

[고정 카드의 1B 평가표](https://huggingface.co/allenai/OLMo-1B-hf/blob/aee7752d9c08ee4775e9b0091426d8410e8f6a89/README.md)는 9개 작업 평균을 OLMo 62.42, Pythia-1B 56.44, TinyLlama-1.1B 61.48로 보고한다. OLMo의 HellaSwag 62.5, ARC-challenge 34.45처럼 작업마다 결과가 다르다. 이 수치는 저자 보고이며 이번 조사에서 실행한 결과가 아니다. 카드의 7B 평가표와 혼동하지 않았고, 비교 모델의 데이터·토큰 규모가 모두 같은 통제 실험도 아니다.

[논문 §4.1](https://arxiv.org/html/2402.00838v3#S4.SS1)은 core 작업을 zero-shot rank classification으로 평가하며, ARC·OpenBookQA는 unconditional normalization, HellaSwag·PIQA·WinoGrande는 per-token normalization을 설명한다. 다만 카드 1B 표의 모든 실행 인자와 이 HF revision에 대한 정확한 매핑은 별도로 검증하지 못했다. 객관식 선택지 우도 평가를 자유로운 대화 응답의 품질이나 한국어 능력 보장으로 해석하지 않는다.

[SmolLM2 분석](2026-10-23-smollm2-1-7b-instruct.md)의 모델은 SFT·DPO를 거친 instruct 체크포인트이고 이 모델은 base다. 대화 품질을 바로 우열 비교하기보다 사전학습·체크포인트 변화 연구나 직접 fine-tuning 실험의 출발점으로 보는 편이 적절하다. 영어 중심이며 최신 사실의 정확성·안전한 답변·한국어 업무 성능은 직접 평가해야 한다. [카드의 용도·한계](https://huggingface.co/allenai/OLMo-1B-hf/blob/aee7752d9c08ee4775e9b0091426d8410e8f6a89/README.md).

전체 F32 가중치만 계산하면 `1,176,764,416×4=4,707,057,664 bytes`, 약 4.71GB(십진 단위)다. 가중치 용량 계산이며 VRAM 실측·최소 요구량이 아니다. KV cache·activation·런타임과 batch에 추가 메모리가 필요하다.
