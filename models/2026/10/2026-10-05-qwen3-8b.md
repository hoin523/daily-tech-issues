## 구조

아래 설정값은 [고정 revision config.json](https://huggingface.co/Qwen/Qwen3-8B/blob/b968826d9c46dd6066d109eabc6255188de91218/config.json)을 직접 조회했다.

| 항목 | 확인값 | 해석 |
|---|---|---|
| 구조 | Qwen3ForCausalLM, dense | 다음 토큰을 예측하는 decoder 모델 |
| 총 파라미터 | 약 8.2B | 모델 카드 표기; 비임베딩 약 6.95B |
| 레이어 | 36 | num_hidden_layers, 학습 epoch와 무관 |
| hidden size | 4,096 | 토큰별 표현의 폭 |
| FFN intermediate | 12,288 | 블록 내부 피드포워드 차원 |
| Q / KV heads | 32 / 8 | GQA 구성 |
| head dimension | 128 | config에 명시된 값 |
| RoPE theta | 1,000,000 | 위치 표현 설정, rope_scaling은 null |
| sliding window | 사용하지 않음 | use_sliding_window=false |
| 저장 dtype | bfloat16 | 실제 학습 정밀도를 확정하는 값은 아님 |
| 임베딩 공유 | false | 입력 임베딩과 출력 가중치 비공유 |
| vocab_size | 151,936 | 설정상 슬롯 수; 토크나이저 유효 어휘 수와 구분 |
| MoE·멀티모달 | 해당 없음 | 전문가 라우팅·이미지 인코더 없음 |

파라미터 수의 근거는 위 모델 카드다. Dense 구조에서는 전문가 일부를 선택하는 MoE식 활성 파라미터 구분이 없으며, 임베딩 조회까지 포함해 모든 파라미터가 매 토큰에 동일하게 계산된다는 뜻은 아니다.

토큰 표현은 36개 블록을 거치며 앞선 토큰을 참조하고 변환된다. GQA는 32개 query head가 8개 key/value head를 공유하는 방식이다. 비율은 `32 / 8 = 4`로, KV 캐시를 절약하는 구조적 이유가 되지만 실제 속도 향상률은 측정하지 않았다. [기술 보고서 §2](https://arxiv.org/html/2505.09388v1#S2)는 SwiGLU, RMSNorm, RoPE와 QK-Norm도 설명한다.

### 컨텍스트 수치를 구분해야 하는 이유

모델 카드는 기본 32,768 토큰과 YaRN 적용 시 131,072 토큰을 구분한다. 반면 이번 config의 max_position_embeddings는 40,960이고 rope_scaling은 null이다. 설정의 위치 상한을 검증된 장문 처리 품질이나 자동 128K 지원으로 해석하지 않는다. [모델 카드](https://huggingface.co/Qwen/Qwen3-8B/blob/b968826d9c46dd6066d109eabc6255188de91218/README.md), [설정](https://huggingface.co/Qwen/Qwen3-8B/blob/b968826d9c46dd6066d109eabc6255188de91218/config.json).

## 학습: 알려진 과정과 비어 있는 값

[공식 발표](https://qwenlm.github.io/blog/qwen3/)는 계열 사전학습 데이터 규모를 약 36조 토큰으로 설명한다. 일반 지식, STEM·코딩 강화, 장문 확장의 세 단계다. 이 수치를 8B 모델의 고유 데이터 수나 epoch로 환산하지 않는다.

[기술 보고서 §4.5](https://arxiv.org/html/2505.09388v1#S4.SS5)는 작은 모델에 strong-to-weak distillation을 적용한다고 설명한다. 따라서 계열의 대형 모델에 설명된 CoT·reasoning RL·thinking fusion·general RL 네 단계를 8B가 모두 직접 실행했다고 옮겨 적지 않는다.

| 학습 항목 | 사전학습 | 8B 후처리 |
|---|---|---|
| 방식 | 3단계 계열 사전학습 | 큰 모델 지식의 증류; 세부사항은 보고서 §4.5 참조 |
| 데이터·토큰 규모 | 계열 약 36조 토큰 | 8B 전용 총량 확인 불가 |
| epoch | 확인 불가 | 확인 불가 |
| optimizer step | 확인 불가 | 확인 불가 |
| batch / gradient accumulation | 8B 전용 설정 확인 불가 | 확인 불가 |
| learning rate / scheduler | 8B 전용 설정 확인 불가 | 확인 불가 |
| optimizer | 8B 전용 설정 확인 불가 | 확인 불가 |
| 학습 precision / 하드웨어 | 8B 전용 설정 확인 불가 | 확인 불가 |
| DPO / LoRA | 적용 근거 확인 불가 | 적용 근거 확인 불가 |

‘확인 불가’는 이번 조사에서 재현 가능한 8B 전용 학습 설정을 확인하지 못했다는 뜻이며, 모든 공개 자료에 없다는 주장과 구분한다. Epoch는 학습 데이터 전체를 반복한 횟수, step은 업데이트 횟수, layer는 네트워크 깊이다. 추론에서 길게 생각하는 토큰 수도 epoch가 아니다.

## 평가와 관련 모델 비교

[기술 보고서 표 6](https://arxiv.org/html/2505.09388v1)은 **Base 모델끼리** 비교한다. MMLU에서 Qwen3-8B-Base는 76.89, Qwen2.5-7B-Base는 74.16이며, MATH에서는 각각 60.80과 49.80이다. 이는 저자 보고 수치이며 여기서 분석하는 후처리 체크포인트의 직접 측정값으로 사용하지 않는다. 평가 프롬프트·샷 수·출력 예산을 맞추지 않은 외부 결과와 바로 비교해서도 안 된다.

구조 비교로 보면 Qwen3-14B는 40개 레이어·40/8 heads, Qwen3-30B-A3B는 48개 레이어·32/4 heads에 128개 전문가 중 토큰당 8개를 선택한다. 8B는 작은 dense 모델이라 전문가 라우팅 없이 운용할 수 있지만, 그 사실만으로 특정 MoE보다 빠르거나 정확하다고 결론 낼 수 없다. [공식 구조 표](https://qwenlm.github.io/blog/qwen3/).

## 사용 판단

Thinking과 non-thinking을 같은 모델에서 전환할 수 있어 복잡한 질의와 빠른 대화를 함께 실험하기에 적합하다. 이미지·음성 입력은 이 체크포인트의 역할이 아니다. 실제 한국어 품질, 지연 시간, 메모리는 자신의 입력과 실행 환경에서 별도 평가해야 한다. [모델 카드](https://huggingface.co/Qwen/Qwen3-8B/blob/b968826d9c46dd6066d109eabc6255188de91218/README.md).

가중치만 BF16으로 저장한다고 가정하면 `8.2×10^9 × 2 bytes = 16.4 GB`(십진 단위)다. 이는 계산값이며 VRAM 실측이나 최소 요구량이 아니다. KV 캐시, 임시 버퍼, 런타임과 배치·컨텍스트 길이가 추가 메모리를 요구한다.
