# DETR ResNet-50: 6+6층 Transformer와 100개 object query로 찾는 물체

조사일: 2026-10-29 KST. 공개 설정·원 논문·코드를 분석했으며 가중치 다운로드나 추론·학습은 실행하지 않았다.

## 선정과 식별

모델 ID는 `facebook/detr-resnet-50`, revision은 `1d5f47bd3bdd2c4bbfa585418ffe6da5028b4c0b`다. [Hub API](https://huggingface.co/api/models/facebook/detr-resnet-50)는 다운로드 113,623·좋아요 990을 반환했고 [페이지](https://huggingface.co/facebook/detr-resnet-50)는 다운로드 기간을 last month로 표시한다. 사용 관심도이지 성능 증거가 아니다. 기존 models·issues 전체 기록을 읽어 DETR 및 동일 가중치 변형 분석이 없음을 확인했다. 최근 언어·검색 모델에 이어 물체 탐지를 선정했다.

개발 조직은 Facebook AI이고 이 체크포인트는 COCO 2017 물체 탐지용 DETR다. backbone은 ImageNet 사전학습 ResNet-50을 활용한다. 생성형 LLM이나 이미지 생성 모델이 아니다. 라이선스는 Apache-2.0이다. [고정 카드](https://huggingface.co/facebook/detr-resnet-50/blob/1d5f47bd3bdd2c4bbfa585418ffe6da5028b4c0b/README.md), [공식 backbone 코드](https://github.com/facebookresearch/detr/blob/29901c51d7fe8712168b8d0d64351170bc0f83e0/models/backbone.py).

[논문 최초 제출](https://arxiv.org/abs/2005.12872)은 2020-05-26이다. 이를 HF 변환 가중치의 최초 배포일로 간주하지 않았으며 해당 날짜는 확인 불가다. HF 카드는 개발팀 자체 작성본이 아니라 Hugging Face 팀 작성본이라고 명시한다. 구조·학습의 검증에는 [공식 저장소](https://github.com/facebookresearch/detr/blob/29901c51d7fe8712168b8d0d64351170bc0f83e0/README.md)와 논문을 함께 사용했다.

## 구조

[고정 config](https://huggingface.co/facebook/detr-resnet-50/blob/1d5f47bd3bdd2c4bbfa585418ffe6da5028b4c0b/config.json) 및 [공식 DETR 구현](https://github.com/facebookresearch/detr/blob/29901c51d7fe8712168b8d0d64351170bc0f83e0/models/detr.py), [Transformer 구현](https://github.com/facebookresearch/detr/blob/29901c51d7fe8712168b8d0d64351170bc0f83e0/models/transformer.py)을 대조했다.

| 항목 | 확인값·의미 |
|---|---|
| 전체 파라미터 | 41,631,008, Hub API safetensors 메타데이터 |
| 이미지 backbone | ResNet-50, dilation=false; DC5 변형과 구분 |
| Transformer 깊이 | encoder 6 + decoder 6 |
| hidden dimension | 256 |
| encoder·decoder FFN | 각각 2,048 |
| attention heads | 양쪽 8, 표준 multi-head attention |
| head dimension | 256÷8=32, 균등 분할 계산 |
| object queries | 학습 가능한 100개, 각 256차원 |
| 위치 표현 | 이미지 특징 격자의 2D sine encoding + 학습 가능한 object query 위치 |
| decoder 출력 head | 클래스 선형 head + 좌표 4개를 예측하는 3층 MLP |
| 활성화 / dropout | ReLU / 0.1 |
| box 손실 계수 | L1=5, generalized IoU=2 |
| matching cost | class=1, L1=5, GIoU=2 |
| no-object 분류 가중치 | eos_coefficient=0.1 |
| MoE·KV head 축소 | 해당 없음 |

ResNet의 특징 맵을 1×1 convolution으로 256차원에 맞춘 뒤 공간 격자를 토큰처럼 펼쳐 encoder에 넣는다. Decoder에서는 100개 query가 서로를 참조하고 encoder의 이미지 특징에 cross-attention한다. 각 slot은 클래스와 box를 병렬 예측한다. ‘decoder 6층’은 다음 단어를 한 개씩 생성하는 6회 반복과 다르다. [논문 §3](https://arxiv.org/html/2005.12872v3#S3), [구현](https://github.com/facebookresearch/detr/blob/29901c51d7fe8712168b8d0d64351170bc0f83e0/models/detr.py).

100은 후보 slot 수로, 입력 텍스트 길이나 항상 검출되는 물체 수가 아니다. 물체가 없는 slot은 no-object로 분류한다. 라벨 매핑에 0~90 슬롯이 있다고 COCO의 실제 평가 범주가 91개라고 세지 않는다. COCO object detection은 80개 범주이고 ID에 빈 구간이 있으며 구현은 추가 no-object 출력을 둔다. [공식 구현](https://github.com/facebookresearch/detr/blob/29901c51d7fe8712168b8d0d64351170bc0f83e0/models/detr.py).

Config의 `num_hidden_layers=6`만 읽으면 encoder·decoder 두 부분을 놓친다. `max_position_embeddings=1024`도 이 모델이 최대 1,024개 픽셀이나 텍스트 토큰만 받는다는 의미가 아니다. 본 모델의 공간 위치 표현은 sine 방식이며 입력 크기와 backbone 특징 맵에 따라 공간 길이가 달라진다. [config](https://huggingface.co/facebook/detr-resnet-50/blob/1d5f47bd3bdd2c4bbfa585418ffe6da5028b4c0b/config.json), [위치 구현](https://github.com/facebookresearch/detr/blob/29901c51d7fe8712168b8d0d64351170bc0f83e0/models/position_encoding.py).

## 일대일 matching은 왜 필요한가

정답 box에는 본래 정해진 출력 순서가 없다. 같은 고양이를 여러 query가 제각각 맡으면 감독 신호도 모호해진다. DETR은 예측과 정답 사이의 클래스·좌표 비용을 계산해 Hungarian algorithm으로 일대일 대응을 찾는다. 대응된 box에 L1·GIoU 손실을 주고 나머지 slot은 no-object로 학습한다. 이 set prediction 설계는 anchor와 중복 box를 합치는 NMS 중심 절차의 필요성을 줄인다. [논문 §3.1](https://arxiv.org/html/2005.12872v3#S3.SS1), [matcher 코드](https://github.com/facebookresearch/detr/blob/29901c51d7fe8712168b8d0d64351170bc0f83e0/models/matcher.py).

Matching은 학습 시 정답과 대응시키는 과정이다. 추론할 때 사용자가 정답 box를 제공하거나 Hungarian matching을 다시 실행해야 한다는 뜻은 아니다. 출력 후 원 이미지 좌표로 복원하고 confidence threshold로 고르는 처리까지 없어지는 것도 아니다. [공식 postprocessor](https://github.com/facebookresearch/detr/blob/29901c51d7fe8712168b8d0d64351170bc0f83e0/models/detr.py), [고정 카드](https://huggingface.co/facebook/detr-resnet-50/blob/1d5f47bd3bdd2c4bbfa585418ffe6da5028b4c0b/README.md).

## 학습: 300 epoch 설명과 500 epoch 모델을 구별

[HF 카드](https://huggingface.co/facebook/detr-resnet-50/blob/1d5f47bd3bdd2c4bbfa585418ffe6da5028b4c0b/README.md)는 300 epochs·16 V100·GPU당 4장·batch 64를 적고 AP 42.0을 제시한다. 반면 [개발팀 model zoo](https://github.com/facebookresearch/detr/blob/29901c51d7fe8712168b8d0d64351170bc0f83e0/README.md)는 R50 AP 42.0 체크포인트의 schedule을 **500**으로 명시한다. 같은 README의 재현용 기본 명령은 300 epoch다. 따라서 서로 다른 설정을 하나의 확정된 HF 학습 이력으로 합치지 않았다.

| 항목 | 검증한 범위 |
|---|---|
| 사전학습 | ImageNet ResNet-50 backbone; 그 사전학습의 전체 설정은 이번 조사에서 확인 불가 |
| 탐지 학습 데이터 | COCO 2017 train 약 118K images; val 약 5K |
| epoch | HF 카드 300, 공식 AP42.0 model zoo 500; 이 revision의 원 로그 대응은 확인 불가 |
| optimizer steps | 해당 HF revision의 정확한 값 확인 불가 |
| optimizer | 공식 recipe AdamW |
| learning rate | Transformer·head 1e-4, backbone 1e-5 |
| scheduler | 공식 main.py는 StepLR; 원 체크포인트의 drop 시점은 이번 조사에서 확인 불가 |
| weight decay / gradient clip | 공식 recipe 1e-4 / global norm 0.1 |
| batch / accumulation | 카드 batch64; 공식 main.py의 배치는 프로세스별 설정. HF 원 실행 accumulation 확인 불가 |
| precision | HF 원 학습 precision 확인 불가; API의 F32 저장값에서 추정하지 않음 |
| 하드웨어 | 카드 16 V100, 공식 재현 안내는 8 V100; 동일 실행이라고 취급하지 않음 |
| SFT·DPO·RL·LoRA | 별도 적용 근거 확인 불가 |

공식 recipe의 값은 [main.py](https://github.com/facebookresearch/detr/blob/29901c51d7fe8712168b8d0d64351170bc0f83e0/main.py) 및 [README](https://github.com/facebookresearch/detr/blob/29901c51d7fe8712168b8d0d64351170bc0f83e0/README.md)에서 확인했다. 현재 코드의 기본값이 배포 가중치를 만든 정확한 실행 인자라는 뜻은 아니다. Backbone 사전학습과 COCO 지도학습을 구분하며, 500 epochs를 500 optimizer steps나 decoder layer 수로 해석하지 않는다.

Config의 `auxiliary_loss=false`도 학습 당시 모든 중간 decoder loss를 껐다는 증거는 아니다. [논문 §3.2](https://arxiv.org/html/2005.12872v3#S3.SS2)는 중간 decoder의 보조 손실을 설명하고 공식 코드의 기본 학습도 이를 제공한다. 추론용 저장 설정과 원 학습 설정을 분리해 읽어야 한다.

입력 전처리도 나눠 보아야 한다. [고정 전처리](https://huggingface.co/facebook/detr-resnet-50/blob/1d5f47bd3bdd2c4bbfa585418ffe6da5028b4c0b/preprocessor_config.json)는 짧은 변 800·긴 변 최대 1333과 ImageNet 평균·표준편차를 사용한다. 공식 **학습** 코드는 flip과 crop, 짧은 변 480~800의 여러 scale을 사용하고, **검증**은 짧은 변 800으로 설정한다. HF 카드가 연결한 ViT 전처리 링크 대신 직접 [DETR COCO 코드](https://github.com/facebookresearch/detr/blob/29901c51d7fe8712168b8d0d64351170bc0f83e0/datasets/coco.py)를 확인했다.

## 평가·관련 모델·사용 판단

카드와 공식 model zoo 모두 COCO 2017 val의 box AP 42.0을 보고한다. 개발팀 model zoo에서 R50-DC5는 43.3, R101은 43.5다. 이는 저자 평가이며 여기서 재측정하지 않았다. AP는 단일 이미지의 confidence 0.42나 전체 box 정확도 42%가 아니며 IoU threshold·recall 조건에 걸친 탐지 평가다. 다른 해상도·학습 schedule·backbone의 점수를 같은 비용의 비교로 해석하지 않는다. [공식 평가표](https://github.com/facebookresearch/detr/blob/29901c51d7fe8712168b8d0d64351170bc0f83e0/README.md).

논문은 작은 물체 탐지와 긴 학습 schedule을 개선 과제로 논의한다. 모델명에 Transformer가 있다고 작은 물체나 붐비는 현장에 자동으로 유리하다고 보장할 수 없다. 원 모델은 COCO 범주를 탐지하며 임의의 자연어 라벨을 입력하는 open-vocabulary detector가 아니다. [논문](https://arxiv.org/html/2005.12872v3), [카드](https://huggingface.co/facebook/detr-resnet-50/blob/1d5f47bd3bdd2c4bbfa585418ffe6da5028b4c0b/README.md).

[SigLIP 분석](2026-10-26-siglip-base-patch16-224.md)은 이미지와 문장 전체의 정렬 점수를 계산한다. DETR은 여러 물체의 위치 box와 클래스를 내므로 결과물과 지표가 다르다. 사진에서 사람·자동차 위치를 찾는 실험에는 적합한 기준선이며, 실제 도메인에서는 class mapping·confidence threshold·작은 물체 recall을 직접 검증해야 한다.

F32 가중치 본체의 계산은 `41,631,008×4=166,524,032 bytes`, 약 166.5MB(십진 단위)다. VRAM 실측이나 실시간 처리 보장이 아니다. 이미지 크기·배치에 따른 backbone·attention activation과 런타임 메모리는 별도다.
