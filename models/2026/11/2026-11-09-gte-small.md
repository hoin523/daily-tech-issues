# GTE-small: 12층 encoder와 평균 pooling으로 만드는 384차원 문장 벡터

조사일: 2026-11-09 (한국 시간). 가중치 다운로드·학습·추론 없이 공개 자료를 분석했다.

## 선정과 식별

## 구조와 pooling

| 항목 | 확인값 |
|---|---|
| 유형 | BERT 계열 양방향 Transformer encoder, Dense |
| 크기 | Hub F16 텐서 원소 33,360,000개 + I64 512개. I64 buffer를 trainable parameter로 세지 않는다. 학습 가능한 전체 계수의 직접 집계는 확인 불가. |
| encoder layer | 12 |
| hidden / 출력 벡터 | 384 / 384차원 |
| attention / KV heads | 표준 MHA Q·K·V 각각 12개 |
| head dimension | `384÷12=32`, 구성에서 유도 |
| FFN intermediate | 1,536, GELU |
| 최대 위치 / 위치 표현 | 512, 학습 가능한 absolute position embedding |
| 어휘 / token type | 30,522 / 2 |
| dropout / LayerNorm epsilon | hidden·attention 각각 0.1 / 1e-12 |
| pooling | attention mask로 padding 제외 후 token 평균 |
| Sentence Transformers 후처리 | Normalize 모듈로 L2 정규화 |
| MoE / 생성 decoder | 없음 |

근거: [고정 config](https://huggingface.co/thenlper/gte-small/blob/17e1f347d17fe144873b1201da91788898c639cd/config.json), [pooling 설정](https://huggingface.co/thenlper/gte-small/blob/17e1f347d17fe144873b1201da91788898c639cd/1_Pooling/config.json), [모듈 순서](https://huggingface.co/thenlper/gte-small/blob/17e1f347d17fe144873b1201da91788898c639cd/modules.json), [BERT 공식 라이브러리 구현](https://github.com/huggingface/transformers/blob/v4.28.1/src/transformers/models/bert/modeling_bert.py), [API](https://huggingface.co/api/models/thenlper/gte-small). 구현 태그는 config의 라이브러리 버전과 맞춘 구조 확인용이며 원 학습 코드 commit은 아니다.

토큰마다 384차원 표현을 만들고, 각 layer에서 앞뒤 토큰을 함께 참고한다. 마지막에는 padding이 아닌 위치의 벡터를 평균 내 문장 하나의 벡터로 바꾼다. CLS 한 개만 읽는 방식이 아니다. 정규화한 벡터의 내적은 cosine similarity와 같아 검색 후보의 순서를 비교할 수 있다. 이 점수가 정답 확률이라는 뜻은 아니다. [공식 사용 예제](https://huggingface.co/thenlper/gte-small/blob/17e1f347d17fe144873b1201da91788898c639cd/README.md#usage)

512는 tokenizer가 처리할 특수 토큰을 포함한 길이 한도다. 512단어라는 뜻이 아니며 긴 문서는 잘릴 수 있다. config의 `use_cache=true`를 근거로 이 encoder에 자동회귀 생성 기능이 있다고 해석하지 않는다. [카드 한계](https://huggingface.co/thenlper/gte-small/blob/17e1f347d17fe144873b1201da91788898c639cd/README.md#limitation), [config](https://huggingface.co/thenlper/gte-small/blob/17e1f347d17fe144873b1201da91788898c639cd/config.json)

## 단계별 학습 조건

아래 수치는 논문이 보고한 GTE 학습 recipe다. 기반 MiniLM의 원래 사전학습과 구분하며, HF revision에 연결된 실행 로그까지 확인한 것은 아니다.

| 항목 | 대조 사전학습 | 지도 대조 미세조정 |
|---|---|---|
| epoch | 약 1회 | 1회 |
| step | 50,000 | 총수 미공개 |
| global batch | 16,384 | 128, group size 16 |
| 최대 길이 | 128 | 512 |
| LR | Small 3e-4 | 10분의 1로 감소 → 3e-5, 계산값 |
| optimizer / scheduler | AdamW, linear decay, 초기 5% warm-up | 단계별 별도 상세 확인 불가 |
| 데이터 | 여러 공개 출처에서 얻은 관련 텍스트 쌍 | 약 3M 라벨 쌍과 hard/random negatives |
| precision | FP16 mixed precision | FP16 mixed precision |
| GPU | Small 사전학습 표 2개, 연구 장비 A100 80GB | Small 실행별 개수 확인 불가 |
| accumulation | 미공개 | 미공개 |

근거: [논문 §3.3–3.4, Table 3](https://arxiv.org/html/2308.03281v1). 기반 MiniLM의 원 학습 epoch·step·데이터 규모는 이번 조사에서 확인 불가. DPO·RL·LoRA는 GTE-small의 후속 단계로 보고되지 않았다.

관련 쌍은 가깝게, 비관련 후보는 멀어지게 학습한다. 사전학습은 batch 안의 다른 텍스트를 negative로 쓰고, 미세조정은 어려운 negative도 넣는다. [논문 §3.4](https://arxiv.org/html/2308.03281v1)

사전학습 warm-up은 `50,000×5%=2,500 step`으로 계산된다. 이는 layer 12개나 입력 512토큰과 다른 단위다. 미세조정의 정확한 sample 구성·batch 마지막 처리 없이 약 3M을 batch로 나눠 실제 step 수라고 쓰지 않았다.

## 공개 평가와 비교의 범위

고정 카드가 보고한 영어 MTEB 56개 과제 평균은 **61.36**, retrieval 집계는 **49.46**이다. 분류·군집·검색·STS 등 서로 다른 지표를 모은 당시 결과로, 현재 leaderboard 순위나 한국어 성능을 뜻하지 않는다. 같은 카드의 GTE-base 평균 62.39와 비교할 수 있지만 모델 크기·차원이 달라 비용과 품질을 별도로 평가해야 한다. [고정 평가 표](https://huggingface.co/thenlper/gte-small/blob/17e1f347d17fe144873b1201da91788898c639cd/README.md#metrics)

실용적으로 영어 검색 후보 생성과 중복 문장 탐색에 사용할 수 있다는 것이 이번 분석의 해석이다. RAG 검색기로 쓰더라도 검색 벡터 자체가 답변을 생성하거나 사실을 검증하지 않는다. 영어 전용과 길이 제한이 명시되어 있으므로 한국어 장문에 그대로 적용한 품질은 확인되지 않았다. [카드 한계](https://huggingface.co/thenlper/gte-small/blob/17e1f347d17fe144873b1201da91788898c639cd/README.md#limitation)

[all-MiniLM-L6-v2](../10/2026-10-06-all-minilm-l6-v2.md)와 출력 차원은 같아도 layer 수와 학습 recipe가 다르다. 벡터 차원이 같다는 이유만으로 서로 다른 모델로 만든 기존 검색 인덱스를 섞을 수는 없다. 모델을 교체한다면 같은 모델로 문서와 query를 다시 표현하는 것이 적절하다. 이는 embedding 공간의 일관성에 관한 분석이며 이번에 실행한 인덱스 실험은 아니다.

출처·구성값·중복 여부를 검토했다. 지연 시간·VRAM·검색 정확도의 실측값은 제시하지 않는다.
