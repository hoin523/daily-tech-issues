# EnCodec 24kHz: 4단계 합성곱과 잔차 코드북으로 소리를 압축하기

조사일: 2026-11-08 (한국 시간). 공개 자료 분석이며 가중치 다운로드·추론·학습은 수행하지 않았다.

## 구조와 시간 축 압축

| 항목 | 공개 설정·구현 |
|---|---|
| 입력 | 24,000Hz, mono 1채널 |
| encoder | 초기 convolution → 4개 residual/downsampling 단계 → 2층 LSTM → 최종 convolution |
| downsampling | encoder 순서 `[2,4,5,8]`, 총 320배 |
| decoder | 초기 convolution → 2층 LSTM → `[8,5,4,2]` transposed-convolution 복원 단계 |
| 기본 채널 수 | 32, encoder 단계마다 증가하여 64·128·256·512 |
| 잠재 차원 | 128 (`hidden_size`, `codebook_dim`) |
| residual block | 단계당 1개, 커널 3과 1의 convolution. 내부 채널 압축 비율 2 |
| 입력·출력 convolution 커널 | 7 |
| 처리 방식 | causal convolution, weight normalization, ELU 계열 활성화 |
| chunk / normalization | `chunk_length_s=null`, `normalize=false`. 48kHz 비인과 stereo 모델의 1초 chunk 설정과 구분. |
| RVQ | 최대 32개 코드북, 코드북당 1,024개 항목 |
| 지원 bitrate | 1.5·3·6·12·24 kbps |
| attention heads / 위치 encoding / MoE | 본 codec에는 해당 없음. 별도 entropy language model과 구분. |
| 저장 텐서 규모 | API F32 원소 합계 23,273,218. 코드북 EMA 등 buffer를 제외한 trainable parameter 수는 직접 확인하지 않았다. |

근거: [고정 config](https://huggingface.co/facebook/encodec_24khz/blob/c1dbe2ae3f1de713481a3b3e7c47f357092ee040/config.json), [공식 SEANet 구현](https://github.com/facebookresearch/encodec/blob/0e2d0aed29362c8e8f52494baf3e6f99056b214f/encodec/modules/seanet.py), [24kHz 생성·양자화기 수 계산](https://github.com/facebookresearch/encodec/blob/0e2d0aed29362c8e8f52494baf3e6f99056b214f/encodec/model.py), [API](https://huggingface.co/api/models/facebook/encodec_24khz). 아래 계산은 이 구성에 대한 유도값이다.

1초 파형의 24,000개 sample을 320배 줄이면 잠재 프레임은 **초당 75개**다. 코드북의 1,024개 항목을 구별하려면 `log₂(1024)=10`bit가 필요하므로, entropy coding 전 bitrate는 `75 × 코드북 수 × 10`bit/s다.

| 목표 kbps | 사용 코드북 수, 계산값 |
|---|---|
| 1.5 | 2 |
| 3 | 4 |
| 6 | 8 |
| 12 | 16 |
| 24 | 32 |

이 계산은 헤더·패딩·컨테이너 overhead를 포함하지 않는다. 실제 파일 크기 측정값이 아니다. [공식 bitrate 계산 구현](https://github.com/facebookresearch/encodec/blob/0e2d0aed29362c8e8f52494baf3e6f99056b214f/encodec/model.py)

첫 코드북은 잠재 벡터를 근사하고, 다음 코드북은 남은 오차를 다시 근사한다. 선택된 벡터들을 합쳐 decoder에 넣으면 파형을 복원한다. 더 많은 코드북은 더 많은 정보를 전달하지만 무손실 복원을 뜻하지 않는다. 여기서 RVQ는 **오디오 표현의 양자화**다. 모델 가중치를 저비트로 줄인 변형이라는 뜻은 아니다. [공식 RVQ 구현](https://github.com/facebookresearch/encodec/blob/0e2d0aed29362c8e8f52494baf3e6f99056b214f/encodec/quantization/vq.py)

카드가 설명하는 추가 Transformer entropy 모델은 이 `EncodecModel` 설정 자체의 필수 attention 계층이 아니다. 이 체크포인트만 로드해 논문에서 보고한 추가 압축까지 자동 달성한다고 해석하지 않는다. [codec 구성](https://github.com/facebookresearch/encodec/blob/0e2d0aed29362c8e8f52494baf3e6f99056b214f/encodec/model.py)

## 학습: epoch의 정의가 공개된 사례

| 항목 | 확인 내용 |
|---|---|
| 학습 단계 | encoder·RVQ·decoder를 함께 학습하는 오디오 재구성. 학습 중 discriminator·loss balancing 사용. |
| epoch | 300, **1 epoch=2,000 updates**라는 연구 정의 |
| 총 update | `300×2,000=600,000`, 공개 정의에서 계산 |
| batch | 1초 오디오 64개 |
| optimizer | Adam, LR 3e-4, β1=0.5, β2=0.9 |
| 하드웨어 | A100 GPU 8개 |
| scheduler / accumulation / precision | 검토한 학습 설명에서 미공개 |
| 데이터 | 음성 DNS Challenge 4·Common Voice, 일반 소리 AudioSet·FSD50K, 음악 Jamendo |
| 총 데이터 시간·고유 sample 수 | 이 체크포인트에 대응하는 집계 확인 불가 |
| 후속 SFT·DPO·RL·LoRA | 본 codec의 학습 단계로 보고되지 않음 |

근거: [고정 카드의 학습 절](https://huggingface.co/facebook/encodec_24khz/blob/c1dbe2ae3f1de713481a3b3e7c47f357092ee040/README.md#training-details), [원 논문 §4.4](https://arxiv.org/html/2210.13438v1). 600,000은 공개 update 정의의 산술 결과이며 개별 가중치 파일의 학습 로그를 확인한 값은 아니다.

이 epoch를 데이터 전체를 300번 읽었다는 뜻으로 바꾸면 안 된다. 위 batch·update를 곱해도 혼합·샘플링으로 만들어진 학습 입력량일 뿐 고유 데이터 시간은 아니다. LSTM 2층, RVQ 코드북 32개, 학습 update도 서로 다른 개념이다.

## 평가와 실용적 제약

논문은 clean/noisy speech와 음악에서 MUSHRA 청취 평가, ViSQOL·SI-SNR을 비교한다. 청취 점수는 숨긴 reference·anchor와 같은 평가 조건에 의존한다. codec·bitrate·entropy coding 여부가 다른 결과를 같은 조건의 순위처럼 섞지 않는다. [논문 §4.3–4.5](https://arxiv.org/html/2210.13438v1)

소리 저장·전송을 위한 표현이나 생성 모델의 오디오 토큰화 구성 요소로 활용할 수 있다. 이는 압축·복원 모델이므로 단독으로 텍스트에서 음악을 만들거나 발화를 전사하지 않는다. [사용 설명](https://huggingface.co/facebook/encodec_24khz/blob/c1dbe2ae3f1de713481a3b3e7c47f357092ee040/README.md)

[Whisper large-v3](../10/2026-10-07-whisper-large-v3.md)는 음성에서 텍스트를 예측하고, [MusicGen-small](../10/2026-10-25-musicgen-small.md)은 오디오 코드의 생성에 언어 모델을 사용한다. 오늘 모델은 입력 소리의 이산 표현과 복원을 담당한다. 48kHz stereo EnCodec과 입력 채널·시간 처리 설정을 혼용하지 않아야 한다. [공식 모델 생성 함수](https://github.com/facebookresearch/encodec/blob/0e2d0aed29362c8e8f52494baf3e6f99056b214f/encodec/model.py)

모델이 causal하다는 사실만으로 특정 장치의 실시간 처리나 지연 시간을 보장하지 않는다. 이번 조사에서는 속도·VRAM·청취 품질을 실측하지 않았다.
