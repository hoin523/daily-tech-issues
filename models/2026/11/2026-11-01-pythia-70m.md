# Pythia-70M: 6층 소형 모델로 읽는 143,000 step의 학습 이력

조사일: 2026-11-01 KST. 가중치 다운로드·추론·학습 없이 공개 자료를 분석했다.

## 선정·식별

모델 ID는 `EleutherAI/pythia-70m`, revision은 `a39f36b100fe8a5377810d56c3f4789b9c53ac42`다. [Hub API](https://huggingface.co/api/models/EleutherAI/pythia-70m)는 다운로드 200,810·좋아요 87을 반환했고 [페이지](https://huggingface.co/EleutherAI/pythia-70m)는 다운로드 기간을 last month로 표시했다. 채택 신호이며 품질의 증거가 아니다. 기존 models·issues 전체 파일을 읽어 해당 모델과 같은 가중치 변형 분석이 없음을 확인했다. 기존 OLMo 글의 Pythia-1B 비교 언급은 70M 구조 분석과 다르다.

개발 조직은 EleutherAI이고 영어 다음 토큰 예측·해석가능성 연구용 base 모델이다. 다른 공개 모델에서 SFT한 모델이 아니라 Pile로 사전학습한 계열이며 라이선스는 Apache-2.0이다. 이 모델은 **non-deduplicated** Pile 학습본으로 deduped 모델과 구분한다. [고정 카드](https://huggingface.co/EleutherAI/pythia-70m/blob/a39f36b100fe8a5377810d56c3f4789b9c53ac42/README.md).

계열 논문의 최초 제출은 [arXiv 기록](https://arxiv.org/abs/2304.01373) 기준 2023-04-03이다. 카드에는 2023년 1월 이름 변경 및 초기 버전 재학습 이력이 있어 논문일을 모델 최초 공개일로 쓰지 않았다. 이 revision의 정확한 최초 배포일은 이번 조사에서 확인 불가다.

## 구조

아래는 [고정 config](https://huggingface.co/EleutherAI/pythia-70m/blob/a39f36b100fe8a5377810d56c3f4789b9c53ac42/config.json)와 [공식 70M 학습 설정](https://github.com/EleutherAI/pythia/blob/a19eecb807ec2c79a39ebf18108816e6ffffc1d5/models/70M/pythia-70m.yml)을 대조했다.

| 항목 | 확인값 |
|---|---|
| 구조 | GPTNeoXForCausalLM, dense causal decoder |
| 레이어 / hidden dimension | 6 / 512 |
| FFN intermediate / activation | 2,048 / GELU |
| attention heads | 8, 표준 MHA 계열; KV head 축소 설정 없음 |
| head dimension | 512÷8=64, 균등 분할 계산 |
| 문맥 길이 | 2,048 tokens |
| 위치 표현 | RoPE, base=10,000, rotary_pct=0.25 |
| 회전 차원 | head당 64×0.25=16, 설정 기반 계산 |
| residual | use_parallel_residual=true |
| 입력·출력 임베딩 | 비공유 |
| 어휘 슬롯 | 50,304 |
| normalization | LayerNorm, eps=1e-5 |
| 저장 dtype | float16 |
| MoE·멀티모달 | 해당 없음 |

공식 카드의 파라미터 표는 총 **70,426,624**, non-embedding **18,915,328**개를 제시한다. 반면 API는 F16 항목 70,426,672개와 U8 항목 25,165,824개를 합산한다. 저장된 buffer·부가 항목이 포함될 수 있으므로 그 합계 95,592,496을 학습 파라미터라고 쓰지 않았다. 정확한 항목별 차이는 가중치 파일을 내려받아 검증하지 않았다. [카드](https://huggingface.co/EleutherAI/pythia-70m/blob/a39f36b100fe8a5377810d56c3f4789b9c53ac42/README.md), [API](https://huggingface.co/api/models/EleutherAI/pythia-70m).

각 블록은 앞선 토큰에 대한 attention과 토큰별 MLP 변환을 수행한다. Parallel residual은 같은 블록 입력에서 attention·MLP 경로를 계산해 residual에 결합하는 설계로, 층 자체를 건너뛰거나 시간상 완벽한 병렬 속도를 보장한다는 뜻은 아니다. 부분 RoPE는 각 head의 일부 차원에만 위치 회전을 적용한다. [논문 §2.3](https://arxiv.org/html/2304.01373v2#S2.SS3), [학습 설정](https://github.com/EleutherAI/pythia/blob/a19eecb807ec2c79a39ebf18108816e6ffffc1d5/models/70M/pythia-70m.yml).

이 모델은 작지만 입력·출력 어휘 행렬은 공유하지 않는다. `50,304×512×2=51,511,296`개의 행렬 원소가 두 어휘 행렬에 들어간다고 계산할 수 있다. 카드의 총 파라미터에서 non-embedding 파라미터를 뺀 값과 같으며, 어휘 표현이 소형 모델에서 큰 비중을 차지함을 보여준다. 모든 가중치가 매 토큰에 같은 방식으로 활성화된다는 뜻은 아니다.

## 학습: epoch·step·토큰의 관계가 공개된 사례

[카드](https://huggingface.co/EleutherAI/pythia-70m/blob/a39f36b100fe8a5377810d56c3f4789b9c53ac42/README.md)는 main이 최종 step143000에 대응하며 299,892,736,000 tokens를 처리했다고 명시한다. 같은 크기라도 deduped는 데이터가 다르고, 초기 v0와 재학습 v1도 구분해야 한다. 이번 분석은 현재 카드가 설명하는 재학습본이다.

| 항목 | 공개값·범위 |
|---|---|
| 목표·데이터 | 다음 토큰 예측, 중복 제거하지 않은 Pile |
| 처리 토큰 | 299,892,736,000 |
| optimizer steps | 143,000 |
| epoch | 카드 표현상 non-deduped Pile 1 epoch에 조금 못 미침 |
| global batch | 2,097,152 tokens = 1,024 sequences×2,048 |
| microbatch / accumulation | 공식 70M 설정 GPU당32 sequences / gas=1 |
| GPU | 논문 부록 D: 32×A100-40GB |
| optimizer | 공식 설정 type=Adam, betas=(0.9,0.95), eps=1e-8 |
| LR / 최소 LR | 0.001 / 0.0001 |
| scheduler | cosine, lr-decay-iters=143000, warmup=0.01 |
| gradient clipping | 1.0 |
| weight decay | 조회한 70M YAML 0.1; 논문 공통 표 0.01과 차이 |
| precision | FP16·동적 loss scaling 설정 |
| 별도 SFT·DPO·RL·LoRA | 이 base 모델에 적용 근거 확인 불가 |

표는 [개별 70M YAML](https://github.com/EleutherAI/pythia/blob/a19eecb807ec2c79a39ebf18108816e6ffffc1d5/models/70M/pythia-70m.yml), [논문 부록 D·E](https://arxiv.org/html/2304.01373v2#A4), [카드](https://huggingface.co/EleutherAI/pythia-70m/blob/a39f36b100fe8a5377810d56c3f4789b9c53ac42/README.md)에 근거한다. 설정 파일을 실제로 실행하거나 해당 HF revision의 원 학습 로그 전체를 재현하지 않았다. 특히 weight decay는 자료 간 차이가 있으므로 하나의 확정 실행값처럼 통합하지 않는다. 논문은 optimizer type을 Adam이라고 표기하며 확인하지 않은 구현 세부를 근거 없이 AdamW라고 바꾸지 않았다.

계산으로 `32 GPUs×32 sequences/GPU×1 accumulation×2048 tokens=2,097,152 tokens/step`이다. 다시 `143,000×2,097,152=299,892,736,000`으로 카드의 총 처리량과 일치한다. 일정 global batch가 유지된다는 공개 설명 아래의 계산이다. warmup 0.01을 143,000-step 기준 비율로 해석하면 약 1,430 steps이며 이는 설정에서 유도한 값이다. 1 epoch 미만이라는 설명은 학습 데이터의 토큰화·샘플링 정의를 따른 것이지 6개 층이나 154개 checkpoint로부터 추정한 것이 아니다.

모델별 154개 checkpoint는 초기 step0, 초기의 지수 간격 step, 이후 1,000-step 간격 기록을 포함한다. 154 epoch가 아니다. 같은 입력을 여러 checkpoint에 통과시켜 언제 특정 행동이 생기는지 연구할 수 있다. 공개된 대형 계열도 동일 순서의 데이터를 보게 해 크기 비교의 혼동 요인을 줄였다. [카드](https://huggingface.co/EleutherAI/pythia-70m/blob/a39f36b100fe8a5377810d56c3f4789b9c53ac42/README.md), [논문 §2](https://arxiv.org/html/2304.01373v2#S2).

## 평가·관련 모델·용도

논문 부록 G의 최종 **non-deduped zero-shot** 표에서 70M은 LAMBADA(OpenAI) 0.185±0.005, PIQA 0.595±0.011이다. 160M은 각각 0.328±0.007, 0.627±0.011이다. 이는 저자 보고값이고 이번 조사 실측이 아니다. LAMBADA의 문맥 기반 마지막 단어 예측과 PIQA의 물리적 상식 선택은 서로 다른 작업이므로 평균만으로 범용 대화 능력을 단정하지 않는다. [논문 부록 G.1](https://arxiv.org/html/2304.01373v2#A7.SS1).

고정 카드 마지막의 리더보드 표는 HellaSwag 10-shot, MMLU 5-shot 등 서로 다른 few-shot 조건을 표시한다. 그 수치를 논문의 zero-shot 표에 이어 붙여 같은 실험으로 비교하지 않았다. 평가 harness 버전·prompt·정규화와 최종 checkpoint를 맞춰야 하며, 공개 점수로 한국어·최신 사실·대화 안전성을 보장하지 않는다. [고정 카드](https://huggingface.co/EleutherAI/pythia-70m/blob/a39f36b100fe8a5377810d56c3f4789b9c53ac42/README.md).

[OLMo-1B 분석](../10/2026-10-27-olmo-1b.md)과 마찬가지로 공개 학습 연구에 유용하지만, Pythia-70M은 6층·512폭으로 훨씬 작고 임베딩을 공유하지 않는다. 학습 도중 표현 변화, 기억·반복 노출 실험과 교육용 구조 분석에 적합하다. [SmolLM2-Instruct](../10/2026-10-23-smollm2-1-7b-instruct.md)처럼 지시 후처리를 마친 대화 모델과 구분하며, 사용자용 챗봇의 대체품으로 성능을 기대하기 어렵다.

카드 파라미터 수를 기준으로 FP16 가중치만 계산하면 `70,426,624×2=140,853,248 bytes`, 약 140.9MB(십진 단위)다. 저장 buffer·헤더·런타임·KV cache와 activation은 제외한 계산으로 VRAM 실측이나 최소 요구량이 아니다.
