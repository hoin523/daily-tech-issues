# DDPM CIFAR-10 32: 4개 해상도의 U-Net과 1,000개 노이즈 시점

조사일: 2026-11-02 KST. 가중치 다운로드·추론·학습 없이 공개 설정·논문·코드를 분석했다.

## 선정과 식별

모델 ID는 `google/ddpm-cifar10-32`, revision은 `267b167dc01f0e4e61923ea244e8b988f84deb80`다. [Hub API](https://huggingface.co/api/models/google/ddpm-cifar10-32)는 다운로드 36,201·좋아요 103을 반환했고 [모델 페이지](https://huggingface.co/google/ddpm-cifar10-32)는 다운로드 기간을 last month로 표시했다. 인기도는 생성 품질의 증거가 아니다. 기존 models·issues 전체 파일을 읽어 동일 모델·계열 구조 분석이 없음을 확인했다. 최근 텍스트·분류 모델에서 무조건부 이미지 생성으로 분야를 바꿨다.

Hub 배포 조직은 Google이며 원 논문 저자는 Jonathan Ho·Ajay Jain·Pieter Abbeel, 논문 소속은 UC Berkeley다. 배포 namespace를 연구진 소속과 동일시하지 않는다. 용도는 CIFAR-10 분포의 **32×32 RGB 무조건부 생성**이고 Hub 라이선스는 Apache-2.0이다. 다른 공개 기반 모델에서 fine-tuning됐다는 근거는 확인 불가다. [고정 카드](https://huggingface.co/google/ddpm-cifar10-32/blob/267b167dc01f0e4e61923ea244e8b988f84deb80/README.md), [논문](https://arxiv.org/html/2006.11239v2).

논문의 최초 제출은 [arXiv 기록](https://arxiv.org/abs/2006.11239) 기준 2020-06-19다. HF 변환 체크포인트의 정확한 최초 배포일은 이번 조사에서 확인 불가이며 논문일로 대신하지 않았다.

## 구조: LLM 레이어 표 대신 U-Net 해상도로 읽기

[고정 config](https://huggingface.co/google/ddpm-cifar10-32/blob/267b167dc01f0e4e61923ea244e8b988f84deb80/config.json), [pipeline 구성](https://huggingface.co/google/ddpm-cifar10-32/blob/267b167dc01f0e4e61923ea244e8b988f84deb80/model_index.json)과 [원 CIFAR 모델 설정](https://github.com/hojonathanho/diffusion/blob/1e0dceb3b3495bbe19116a5e1b3596cd0706c543/scripts/run_cifar.py)을 확인했다.

| 항목 | 확인값·의미 |
|---|---|
| 네트워크 | UNet2DModel, 픽셀 공간 diffusion |
| 파라미터 | 35,746,307, API F32 메타데이터 |
| 입력·출력 채널 | 3 / 3 |
| sample_size | 32, RGB 이미지 한 변 |
| 채널 단계 | [128,256,256,256] |
| 해상도 단계 | 32→16→8→4, 3회 2배 축소를 가정한 계산 |
| down block | Down, AttnDown, Down, Down |
| up block | Up, Up, AttnUp, Up |
| layers_per_block | 2, down 쪽 해상도별 residual 블록 설정 |
| 정규화·활성화 | GroupNorm 32 groups, eps=1e-6 / SiLU |
| 시간 조건 | sinusoidal positional timestep embedding |
| 텍스트 encoder·VAE | pipeline 구성에 없음 |
| MoE·LLM context·KV heads | 해당 없음 |

논문은 4개 해상도, 해상도별 residual 블록과 16×16 위치의 attention을 설명한다. Down에서 이미지를 압축한 특징을 up에서 복원할 때 skip connection으로 세부 정보를 가져온다. 병목·up 쪽 추가 블록을 포함하므로 `layers_per_block=2`를 모델 전체가 2층이라고 읽거나 단순히 4×2=8층이라고 총합하지 않았다. [논문 부록 B](https://arxiv.org/html/2006.11239v2#A2), [원 U-Net 구현](https://github.com/hojonathanho/diffusion/blob/1e0dceb3b3495bbe19116a5e1b3596cd0706c543/diffusion_tf/models/unet.py).

배포 config의 attention_head_dim=null은 숫자로 된 head 폭을 직접 명시하지 않은 것이다. LLM식 head 수를 임의로 채우지 않았다. 원 모델은 16×16 해상도에서 self-attention을 사용하고 병목에도 attention이 포함되므로 down_block_types 목록만으로 attention 전체 개수를 세지 않았다. [원 구현](https://github.com/hojonathanho/diffusion/blob/1e0dceb3b3495bbe19116a5e1b3596cd0706c543/diffusion_tf/models/unet.py).

## 노이즈를 예측한다는 의미

학습에서는 깨끗한 이미지에 특정 시점 t의 노이즈를 섞고 U-Net이 섞인 노이즈를 맞히도록 한다. 각 학습 예제에 t를 샘플링하므로 optimizer 업데이트 한 번마다 1,000회 U-Net을 반드시 실행하는 방식이 아니다. 생성은 무작위 노이즈에서 시작해 역과정을 반복한다. [논문 §3](https://arxiv.org/html/2006.11239v2#S3), [학습 코드](https://github.com/hojonathanho/diffusion/blob/1e0dceb3b3495bbe19116a5e1b3596cd0706c543/scripts/run_cifar.py).

[고정 scheduler](https://huggingface.co/google/ddpm-cifar10-32/blob/267b167dc01f0e4e61923ea244e8b988f84deb80/scheduler_config.json)는 num_train_timesteps=1000, linear beta schedule, beta_start=0.0001, beta_end=0.02, variance_type=fixed_large, clip_sample=true다. 여기서 1,000은 노이즈 시간축의 이산 구간 수이고 **학습 epoch나 optimizer step 수가 아니다**. 학습 LR scheduler의 linear warmup과 노이즈 beta의 linear schedule도 별개다.

텍스트·class 조건을 받는 구성 요소가 없으므로 ‘고양이를 그려줘’ 같은 prompt를 넣어 종류를 지정하는 모델이 아니다. 모델 페이지의 자동 생성 사용 예시에 prompt가 보이더라도, 분석은 고정 model_index·카드의 무조건부 파이프라인에 근거했다. DDIM·PNDM 등 다른 sampler로 실행할 수 있다는 카드 설명도 해당 sampler의 속도·품질을 여기서 검증했다는 의미는 아니다. [고정 카드](https://huggingface.co/google/ddpm-cifar10-32/blob/267b167dc01f0e4e61923ea244e8b988f84deb80/README.md), [pipeline](https://huggingface.co/google/ddpm-cifar10-32/blob/267b167dc01f0e4e61923ea244e8b988f84deb80/model_index.json).

## 학습: 논문 실험과 배포 가중치의 확인 범위

공식 원 저장소의 [CIFAR 학습 함수](https://github.com/hojonathanho/diffusion/blob/1e0dceb3b3495bbe19116a5e1b3596cd0706c543/scripts/run_cifar.py)는 model_mean_type=eps, loss_type=mse, class label을 쓰지 않는 경로를 갖는다. 아래는 원 논문·코드의 공개 설정이며 해당 HF revision의 원 실행 로그를 재현한 값은 아니다.

| 항목 | 원 CIFAR 실험의 공개값 |
|---|---|
| 데이터 | CIFAR-10, 32×32 이미지; class 조건 없이 학습 |
| optimizer updates | 논문 800,000 steps |
| epoch | 배포 revision의 정확한 epoch 확인 불가 |
| batch | 128 images |
| optimizer / LR | Adam / 2e-4 |
| LR warmup | 원 코드 기본 5,000 steps |
| clipping | 원 코드 grad_clip=1.0 |
| augmentation·dropout | random horizontal flip / 0.1 |
| EMA | 논문 decay=0.9999 |
| gradient accumulation | 배포 revision의 실제 실행값 확인 불가 |
| precision | 코드 denoiser 입력 tf.float32; 전체 학습의 모든 연산 정밀도·원 배포 실행 대응은 확인 불가 |
| 하드웨어 | 논문 TPU v3-8; 배포 원 로그로의 직접 대응 확인 불가 |
| SFT·DPO·RL·LoRA | 별도 적용 근거 확인 불가 |

출처는 [논문 부록 B](https://arxiv.org/html/2006.11239v2#A2)와 [원 학습 코드](https://github.com/hojonathanho/diffusion/blob/1e0dceb3b3495bbe19116a5e1b3596cd0706c543/scripts/run_cifar.py)다. 모델 카드의 일반 학습 notebook 링크를 이 가중치를 실제로 만든 recipe라고 취급하지 않았다. ‘확인 불가’는 이번 조사에서 checkpoint 단위 근거를 확인하지 못했다는 뜻이며 모든 자료가 미공개라고 단정하는 말과 다르다.

가정 계산으로 50,000개 학습 이미지를 균일하게 처리하고 batch128·800,000 updates가 끝까지 유지된다면 `800,000×128÷50,000=2,048` 데이터셋 상당량이다. 이는 반복 노출량의 환산이며 검증된 epoch 기록이 아니다. 데이터 pipeline·재시작·선택 checkpoint에 따라 다를 수 있다. 한편 추론 1,000 denoising steps는 같은 네트워크를 노이즈 시점에 따라 반복 적용하는 과정이며 1,000개 서로 다른 레이어가 아니다.

## 평가·활용·관련 모델

논문은 unconditional CIFAR-10에서 Inception score 9.46과 FID 3.17을 보고하며 카드도 이를 인용한다. 부록은 50,000 생성 sample로 평가하고 학습 중 최소 FID 시점의 점수를 보고했다고 설명한다. 이는 저자 원 실험 결과이지 현재 HF revision과 scheduler로 다시 측정한 점수가 아니다. [논문 부록 B](https://arxiv.org/html/2006.11239v2#A2), [카드](https://huggingface.co/google/ddpm-cifar10-32/blob/267b167dc01f0e4e61923ea244e8b988f84deb80/README.md).

FID는 생성·참조 이미지 특징 분포 비교이며 낮을수록 좋다. 샘플 수·참조 통계·평가 구현·sampler 조건이 바뀌면 숫자를 직접 비교하기 어렵다. 2020년 논문의 성과를 현재 최고 성능이라고 표현하지 않았고, LSUN 256×256 실험 결과를 이 CIFAR-10 체크포인트에 붙이지 않았다.

[SDXL 분석](../10/2026-10-08-sdxl-base-1-0.md)은 텍스트 조건·latent 공간의 대형 이미지 모델인 반면 이 모델은 픽셀 공간의 작은 무조건부 U-Net이다. 노이즈 시간축·MSE 학습·sampler 작동을 이해하는 교육·연구 기준선에 적합하다. 고해상도 작품 제작이나 prompt 기반 제품 이미지를 만드는 용도로 해석하지 않는다.

F32 가중치 본체는 `35,746,307×4=142,985,228 bytes`, 약 143.0MB(십진 단위)다. 저장량 계산이며 VRAM 실측·실행 속도 보장이 아니다. 반복 sampling의 실행 시간, batch·activation·런타임 메모리는 별도다.
