# BLIP-2 OPT-2.7B: 32개 query로 이미지 encoder와 언어 모델 연결하기

조사일: 2026-11-04 KST. 공개 문서·설정·코드를 분석했으며 가중치 다운로드·추론·학습은 수행하지 않았다.

## 선정·식별

모델 ID는 `Salesforce/blip2-opt-2.7b`, revision은 `59a1ef6c1e5117b3f65523d1c6066825bcf315e3`다. [Hub API](https://huggingface.co/api/models/Salesforce/blip2-opt-2.7b)는 다운로드 398,935·좋아요 448을 반환했고 [페이지](https://huggingface.co/Salesforce/blip2-opt-2.7b)는 다운로드 기간을 last month로 표시한다. 인기도는 품질 증거가 아니다. 기존 models·issues 전체 파일을 읽어 BLIP-2 구조 분석이 없음을 확인했다. [기존 BLIP 분석](../10/2026-10-15-blip-image-captioning-base.md)과 이름은 관련되지만 Q-Former와 동결 LLM을 연결하는 실질적으로 다른 모델이다.

개발 조직은 Salesforce Research, 용도는 이미지 설명·이미지 기반 질문의 텍스트 생성이다. 카드 제목은 **pre-trained only**로, COCO 전용 fine-tuning 모델이나 instruct 후처리 모델과 구분한다. 언어 기반은 `facebook/opt-2.7b`, 시각 계열은 EVA-CLIP ViT-g/14다. Hub 라이선스 표기는 MIT이며 구성 요소 OPT의 원 라이선스·사용 조건은 별도 확인 대상이다. [고정 카드](https://huggingface.co/Salesforce/blip2-opt-2.7b/blob/59a1ef6c1e5117b3f65523d1c6066825bcf315e3/README.md), [공식 모델 설정](https://github.com/salesforce/LAVIS/blob/05cb670f47296522e24e7727e366b4a997d28582/lavis/configs/models/blip2/blip2_pretrain_opt2.7b.yaml), [논문 §3.4](https://arxiv.org/html/2301.12597v3#S3.SS4).

논문 최초 제출은 [arXiv 기록](https://arxiv.org/abs/2301.12597) 기준 2023-01-30이다. 이를 HF 변환 체크포인트의 정확한 최초 공개일로 대신하지 않았다. 해당 배포일은 이번 조사에서 확인 불가다. HF 카드는 개발팀 자체 작성본이 아닌 Hugging Face 팀 작성본임을 명시한다.

## 세 구성 요소의 구조

[고정 config](https://huggingface.co/Salesforce/blip2-opt-2.7b/blob/59a1ef6c1e5117b3f65523d1c6066825bcf315e3/config.json)는 vision·Q-Former 값을 상당수 생략한다. 아래 값은 이를 [Transformers v4.47.0 설정 클래스](https://github.com/huggingface/transformers/blob/v4.47.0/src/transformers/models/blip_2/configuration_blip_2.py)의 기본값으로 복원해 읽은 것이다. 생략된 값을 JSON에 직접 명시된 값이라고 주장하지 않는다.

| 구성 | 깊이 | hidden / FFN | heads / head dimension | 역할 |
|---|---|---|---|---|
| vision encoder | 39 layers | 1,408 / 6,144 | 16 / 88 계산 | 이미지 patch 특징 추출 |
| Q-Former | 12 layers | 768 / 3,072 | 12 / 64 계산 | 32개 query로 시각 특징 압축 |
| OPT decoder | 32 layers | 2,560 / 10,240 | 32 / 80 계산 | 이미지 조건·이전 텍스트에서 다음 토큰 생성 |

각 head dimension은 hidden÷heads의 균등 분할 계산이다. GQA나 MoE 구성은 없다. Vision 39층은 논문이 마지막 ViT layer를 제거하고 두 번째 마지막 출력을 쓰는 설명과 함께 읽어야 한다. Q-Former cross_attention_frequency=2 기본값은 시각 특징을 참조하는 층의 간격이며 2 epoch나 query가 2개라는 뜻이 아니다. [논문 §3](https://arxiv.org/html/2301.12597v3#S3), [설정 클래스](https://github.com/huggingface/transformers/blob/v4.47.0/src/transformers/models/blip_2/configuration_blip_2.py).

이미지는 224×224, patch14이므로 `16×16=256`개 patch이고 CLS를 더하면 257개 시각 토큰이다. 이는 기본 해상도를 가정한 계산이다. 32개 query는 이 시각 특징을 읽어 32×768 표현을 만들고, 학습 가능한 선형 projection이 OPT 입력 폭 2,560으로 바꾼다. 이미지 해상도가 32픽셀이거나 OPT 어휘에 이미지 단어 32개를 새로 넣는다는 뜻은 아니다.

Vision은 학습 가능한 위치 임베딩을 사용하고 OPT는 자체 텍스트 위치 체계를 사용한다. Q-Former config의 max_position_embeddings=512 기본값을 전체 멀티모달 모델의 지원 문맥으로 읽지 않았다. 이번 고정 text_config에 OPT의 최대 위치값이 직접 명시되지 않아 전체 입력·생성 토큰 예산은 실행 OPT 설정으로 추가 확인해야 하며 여기서는 확정하지 않았다. [고정 config](https://huggingface.co/Salesforce/blip2-opt-2.7b/blob/59a1ef6c1e5117b3f65523d1c6066825bcf315e3/config.json).

API 메타데이터의 전체 파라미터는 **3,744,761,856**개(F32)다. 모델명의 2.7B는 OPT 부분이지 전체가 아니다. 논문 표2의 ViT-g+OPT2.7B는 약3.8B total·107M trainable을 구분한다. 학습 가능 파라미터 수가 적어도 동결된 vision·LLM의 forward 계산과 저장 공간이 없어지는 것은 아니다. [API](https://huggingface.co/api/models/Salesforce/blip2-opt-2.7b), [논문 표2](https://arxiv.org/html/2301.12597v3#S4).

## 동작과 두 단계 학습

첫 단계는 동결 이미지 encoder 위에서 Q-Former를 이미지·텍스트에 맞춘다. Image-text contrastive, image-text matching, image-grounded text generation을 함께 이용하되 attention mask를 달리한다. 두 번째 단계는 동결 OPT에 query 출력을 soft visual prompt로 붙여 텍스트 생성 손실로 연결을 학습한다. 추론에서는 이미지를 읽는 query 경로가 OPT 앞에 정보를 공급한다. OPT의 모든 층에 별도 이미지 cross-attention을 추가하는 방식과 다르다. [논문 §3.1~3.3](https://arxiv.org/html/2301.12597v3#S3).

Q-Former는 BERT-base로 초기화하고 새 cross-attention 층을 학습한다. 논문에서 Q-Former 약188M과 표2의 학습 가능107M이 다른 것은 단계별로 사용하는 구성 경로를 구분해야 함을 보여준다. 이 숫자를 모델 전체 활성 파라미터나 추론 FLOPs로 쓰지 않았다. [논문 §3.1 및 표2](https://arxiv.org/html/2301.12597v3#S3.SS1).

| 항목 | 표현 정렬 단계 | OPT 생성 연결 단계 |
|---|---|---|
| steps | 250,000 | 80,000 |
| batch | ViT-g 기준1,680 | OPT 기준1,920 |
| 데이터 | 계열129M 이미지, CapFilt caption | 같은 계열 데이터 |
| epoch | 해당 revision의 정확한 값 확인 불가 | 확인 불가 |
| optimizer | AdamW | AdamW |
| peak LR / warmup | 1e-4 / 2,000 steps | 1e-4 / 2,000 steps |
| scheduler | cosine | cosine, min LR5e-5 |
| weight decay | 0.05 | 0.05 |
| frozen 부분 | 이미지 encoder | 이미지 encoder와 OPT |
| precision | 동결 ViT FP16 | 동결 ViT·OPT FP16 |
| accumulation·전체 학습 dtype | 실제 실행값 확인 불가 | 실제 실행값 확인 불가 |
| 하드웨어 | 이 checkpoint 전용 구성 확인 불가 | 확인 불가 |

표는 [논문 §3.4](https://arxiv.org/html/2301.12597v3#S3.SS4) 및 [공식 모델 설정](https://github.com/salesforce/LAVIS/blob/05cb670f47296522e24e7727e366b4a997d28582/lavis/configs/models/blip2/blip2_pretrain_opt2.7b.yaml)에 근거한다. 논문은 공통 optimizer beta를0.9·0.98로 적지만 두 기호를 모두 beta1로 표기하는 오타가 있어 문맥상 beta2로 해석해야 하는 부분을 구분한다. 논문의 16×A100-40GB·6일/3일 설명은 가장 큰 ViT-g+FlanT5-XXL 예시로, 이 OPT2.7B의 실측 학습 시간으로 옮기지 않았다.

129M은 고유 이미지 규모 설명이며, 웹 이미지당 top-two caption 중 하나를 샘플링한다. 따라서 `250000×1680÷129M` 같은 나눗셈을 정확한 epoch로 쓰지 않았다. Q-Former·projection의 multimodal 사전학습과 EVA·OPT·BERT의 기존 사전학습은 다른 단계다. 기반 모델들의 epoch·step·데이터·배치·LR·optimizer·정밀도·하드웨어 전체 이력은 이번에 개별 검증하지 못해 확인 불가로 남겼다. 별도 DPO·RL·LoRA 적용 근거도 확인 불가다.

## 평가·활용 판단

논문 표2의 **ViT-g+OPT2.7B**는 zero-shot VQAv2 val53.5·test-dev52.3, OK-VQA31.7, GQA34.6을 보고한다. OPT 평가 prompt는 `Question: … Answer:`, beam width5·length penalty−1 조건이다. 저자 공개값이며 현재 HF revision을 직접 실행한 결과는 아니다. 더 큰 FlanT5-XXL의65.0이나 초록의 Flamingo 대비 향상을 이 모델 점수로 쓰지 않았다. [논문 표2 및 §4.1](https://arxiv.org/html/2301.12597v3#S4.SS1).

Zero-shot은 이 VQA 작업의 정답으로 별도 fine-tuning하지 않았다는 평가 조건이며 모든 데이터와 완전히 무관했다는 포괄적 보장은 아니다. 논문의 COCO fine-tuned caption 결과도 pre-trained only checkpoint와 구분해야 한다. 이미지 설명·시각 질의 연구에 적합하지만 개수 세기·작은 글씨·세부 속성·한국어 응답은 직접 검증해야 한다. OPT 기반의 환각·편향 한계도 이어받는다. [카드](https://huggingface.co/Salesforce/blip2-opt-2.7b/blob/59a1ef6c1e5117b3f65523d1c6066825bcf315e3/README.md), [논문 한계](https://arxiv.org/html/2301.12597v3#S5).

API 전체 파라미터 기준 FP16 가중치만 가정하면 `3,744,761,856×2≈7.49GB`(십진 단위)다. 카드의 메모리 표와는 단위·계산 범위가 다를 수 있다. 이 계산은 실측 VRAM·최소 요구량이 아니며 KV cache·activation·vision 입력·런타임이 추가된다. 가중치를 동결했다는 이유로 추론 메모리를107M만 계산하면 안 된다.
